# ig-carousel

לפני הכול: קרא את `context.md`, `voice.md` ו-`compliance.md` שבתיקייה הזו. אם `~/.claude/instagram/voice.md` קיים, הוא גובר על `voice.md` שכאן.

קרוסלה מחזיקה תשומת לב יותר מכל דבר אחר בגריד, כי החלקה נספרת כאינטראקציה וגלילה לא. והיא מקבלת הזדמנות שנייה: אינסטגרם יכולה להציג קרוסלה שוב, מאחת השקופיות הבאות, למי שדילג עליה בפעם הראשונה. לכן שקופית 2 חייבת לעבוד גם לבד.

הפורמט מתגמל רעיון אחד שמפורק לשלבים. הוא מעניש כיתוב שנחתך לחתיכות.

לעורך דין בדיני משפחה זה הפורמט הטבעי: "מה לבדוק לפני", "השלבים בהליך", "שאלות לשאול". רשימה שאנשים שומרים, שולחים לחבר שעובר את אותו דבר, ופותחים שוב לפני פגישה.

## קרוסלה או רילס?

קרוסלה כשלרעיון **יש סדר והוא דורש קריאה חוזרת**: שלבים, מסגרת עם חלקים, שאלות לפני פגישה, רשימה ששווה צילום מסך. רילס כשלרעיון יש תנועה, פנים, או תמורה שצריך לראות קורית. סיפור אישי, הספר וההרצאות עובדים בדרך כלל טוב יותר ברילס, כי הם צריכים את הקול שלו.

אם הרעיון הוא טענה אחת, הוא לא זה ולא זה. העבר אותו ל-`/ig-reel` ותגיד למה.

## ציות לפני כתיבה

בדוק את הבקשה מול `compliance.md`. בקרוסלה זה נופל בדרך כלל על: "שלבים שהובילו לניצחון בתיק" (C3, C4), שקופית "לפני ואחרי" של לקוח (C4, C5), תיק אמיתי כדוגמה (C5, C6), "מדריך במתנה" בשקופית האחרונה (C13), מחירון או "פגישה ראשונה חינם" (C9), לוגואים של כלי תקשורת (C20), השוואה לעורכי דין אחרים (C1). אם יש התנגשות: שורה אחת שאומרת מה ולמה, חלופה שעומדת בכללים, וממשיכים בה.

## המבנה

6 עד 10 שקופיות. המקסימום הוא 20, ו-20 זה כמעט תמיד ספר שאף אחד לא מסיים. פחות מ-5, ואף אחד לא מתחיל להחליק.

```
1         שער       ההוק. עד 6 מילים, גדול מספיק לקריאה בגריד, בגודל תמונה ממוזערת.
                    שורת הבטחה אחת מתחת.
2         הסיכון    למה זה חשוב, במשפט אחד. השקופית הזו היא גם שער שני,
                    אז היא לא יכולה להיות הקדמה.
3 עד N    רעיון אחד בכל שקופית. כותרת של 3 עד 7 מילים, עד 25 מילים מתחת.
                    אם שקופית צריכה פסקה, אלה שתי שקופיות.
N+1       סיכום     הכול כרשימה. השקופית שמצלמים.
אחרונה    בקשה      פעולה אחת: שמירה, שליחה, או "הקישור בביו". רק אחת.
```

## כללים לטקסט של השקופיות

- **השער עושה 80% מהעבודה.** עד 6 מילים, גדול. שום דבר בהמשך לא מציל שער שלא מחליקים ממנו.
- **מידע כללי, לא ייעוץ.** "שאלות לשאול", "מה לבדוק", "איך ההליך עובד". לא "מה לעשות במקרה שלך".
- **טענה משפטית רק אם היא בסיסית וודאית.** כל השאר `[לבדיקה: ...]` או `{{הנקודה המשפטית}}`, וסולי ממלא. שום שקופית לא מרונדרת כשנשאר בה סימון כזה.
- **בלי פסקאות.** אם זה לא נכנס ב-25 מילים, פצל.
- **הסיכום הוא מה שמצלמים ושולחים.** שליחה היא האות החזק ביותר שיש. הוא חייב להיות קריא לבד, בלי הקשר.
- **שקופית הבקשה עומדת בכללים.** "שמרו את זה לפני הפגישה הראשונה" כן. "הקישור בביו" לדף הנחיתה כן. "שלחו לי את ההסכם ואבדוק" לא: זה מזמין מסמכים ופרטים רגישים לאינסטגרם ומבטיח בדיקה של מקרה מסוים. מילת מפתח רק אם `voice.md` מגדיר מה היא שולחת, כמידע כללי שכבר פורסם, ואז REVIEW (C13).
- **ההבהרה.** בשקופית הבקשה או בכיתוב: "מידע כללי, לא ייעוץ משפטי למקרה מסוים." לא בשער.
- **טקסט חלופי (alt text) לשער לפחות,** בעברית. קוראי מסך ואינסטגרם קוראים אותו.

## העיצוב

לפי `context.md`. אל תמציא פלטה. אם יש ב-Project או בתיקייה סקיל מותג או מערכת עיצוב של סולי, היא גוברת על הערכים כאן.

- **רקע** כמעט שחור (`#0E0E0E`). **הדגשה** זהב-ענבר (`#D4A24C`), צבע הדגשה אחד. **טקסט** שמנת (`#F3EEE6`), טקסט משני `#A39D93`. הניגודיות מול הרקע: 8.3:1 לזהב, 16.7:1 לשמנת, 7.2:1 למשני.
- **גופנים:** Frank Ruhl Libre לכותרות, Heebo לטקסט. שניהם מ-Google Fonts.
- **גודל:** 1080x1350 לכל שקופית. שום טקסט מתחת ל-32px, כי קוראים אותו בטלפון בערך בשליש מהגודל האמיתי. כותרת שער סביב 110 עד 120px, כותרת שקופית סביב 72 עד 80px, טקסט 40px.
- **מימין לשמאל:** `<html lang="he" dir="rtl">`. יישור לימין.
- **הגריד חותך.** הגריד בפרופיל חותך פוסטים לפורטרט צר יותר, והיחס המדויק השתנה כבר יותר מפעם אחת. בונים 1080x1350 ומשאירים את טקסט השער באמצע, לפחות 120px מכל קצה, ואז החיתוך לא משנה.
- **ההנדל בכל שקופית,** קטן, בפינה התחתונה. צילומי מסך מסתובבים בלי החשבון. ההנדל מגיע מ-`voice.md`. אם הוא עדיין `{{@הנדל}}`, שאל.
- **מספור בכל שקופית** (3/8). רואים שהסוף מתקרב, ומסיימים יותר. ההנדל והמספור נכתבים בתוך `<bdi dir="ltr">`. בלי זה, בעמוד RTL ה-@ קופץ לסוף ("handle@"), ו-"3 / 8" עם רווחים מתהפך ל-"8 / 3".

## הקבצים

אינסטגרם רוצה 1080x1350 (4:5), JPEG או PNG, עד 20 פריטים. **לא מרנדרים לפני שסולי מאשר את הטקסט.** אחרי האישור: קובץ HTML אחד, `<section>` אחד בגודל 1080x1350 לכל שקופית, ואז PNG לכל שקופית.

ב-claude.ai אין לך את המחשב שלו. אם יש לך סביבת הרצת קוד, נסה בה את אותה דרך ותן לו את קבצי ה-PNG. אם אין, או שהגופנים לא נטענים שם, תן לו את קובץ ה-HTML ואת `render_slides.py` להרצה ב-Mac שלו.

**השלד:**

```html
<!doctype html>
<html lang="he" dir="rtl">
<head>
<meta charset="utf-8">
<link rel="stylesheet" href="https://fonts.googleapis.com/css2?family=Frank+Ruhl+Libre:wght@700&family=Heebo:wght@400;500&display=block">
<style>
  @page { size:1080px 1350px; margin:0; }
  :root { --bg:#0E0E0E; --gold:#D4A24C; --ink:#F3EEE6; --mute:#A39D93; }
  * { margin:0; padding:0; box-sizing:border-box; }
  body { background:var(--bg); }
  section { width:1080px; height:1350px; position:relative; overflow:hidden; break-after:page;
            background:var(--bg); color:var(--ink); padding:160px 120px;
            display:flex; flex-direction:column; justify-content:center; gap:44px;
            font:400 40px/1.5 "Heebo", sans-serif; }
  h1, h2 { font-family:"Frank Ruhl Libre", serif; font-weight:700; color:var(--gold); line-height:1.15; }
  h1 { font-size:116px; }
  h2 { font-size:76px; }
  .rule { width:120px; height:4px; background:var(--gold); }
  footer { position:absolute; inset:auto 120px 72px 120px; display:flex;
           justify-content:space-between; font-size:32px; color:var(--mute); }
</style>
</head>
<body>
<section>
  <h1>{{כותרת השער}}</h1>
  <div class="rule"></div>
  <p>{{שורת ההבטחה}}</p>
  <footer><bdi dir="ltr">{{@הנדל}}</bdi><bdi dir="ltr">1/8</bdi></footer>
</section>
<!-- section לכל שקופית. כל סימון בסוגריים מסולסלים כפולים מוחלף בטקסט המאושר, אחרת הסקריפט לא ירנדר.
     אל תכתוב את הסימון עצמו בהערה: render_slides.py קורא את כל הקובץ, כולל הערות -->
</body>
</html>
```

**הייצוא, עם Playwright** (הדרך שנבדקה). קודם בדוק שהוא מותקן:

```bash
python3 -c "import playwright" || (pip3 install playwright && python3 -m playwright install chromium)
```

ההתקנה מורידה דפדפן Chromium שלם. בקש אישור לפני שאתה מריץ אותה. אם `pip3` מסרב עם `externally-managed-environment` (קורה עם Python של Homebrew), צור סביבה נפרדת והרץ ממנה:

```bash
python3 -m venv ~/.venvs/ig && ~/.venvs/ig/bin/pip install playwright && ~/.venvs/ig/bin/python -m playwright install chromium
```

ואז `~/.venvs/ig/bin/python` במקום `python3` בפקודת הרינדור. אם הספרייה מותקנת אבל הרינדור נכשל עם `Executable doesn't exist`, חסר הדפדפן: `python3 -m playwright install chromium`.

הסקריפט `render_slides.py` נמצא בתיקייה הזו:

```bash
python3 render_slides.py carousel.html
```

הוא עוצר אם נשארו `{{...}}` או `[לבדיקה]` בשקופיות, ובודק ש-Frank Ruhl Libre ו-Heebo באמת נטענו לפני שהוא מייצא.

התוצאה: `slides/slide-01.png` ואילך, כל אחד 1080x1350 בדיוק. פתח שניים מהם ובדוק בעיניים: כיוון, גופן, ושההנדל והמספור במקום.

**אם הגופנים לא נטענים** (בלי אינטרנט, או ש-Google Fonts חסום), הסקריפט עוצר ולא מייצא שקופיות בגופן חלופי. הפתרון: להוריד את שתי המשפחות מ-fonts.google.com (כפתור ההורדה בעמוד של Heebo ובעמוד של Frank Ruhl Libre), לקחת מכל ZIP את קובץ ה-TTF המשתנה (בשם יש `[wght]`), לשים את שניהם בתיקייה `fonts/` ליד ה-HTML, ולהחליף את שורת ה-`<link>` בזה, עם שמות הקבצים כפי שהורדו:

```css
@font-face { font-family:"Frank Ruhl Libre"; src:url("fonts/FrankRuhlLibre[wght].ttf"); font-weight:300 900; }
@font-face { font-family:"Heebo"; src:url("fonts/Heebo[wght].ttf"); font-weight:100 900; }
```

גם גופנים שמותקנים ב-Mac עצמו עובדים.

**בלי Playwright ובלי אפשרות להתקין:** Chrome מהשורה, ל-PDF בעמוד לכל שקופית (ה-`@page` בשלד דואג לגודל), ואז PNG לכל עמוד:

```bash
"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --headless \
  --no-pdf-header-footer --print-to-pdf=slides.pdf "file://$PWD/carousel.html"
pdftoppm -png -scale-to-x 1080 -scale-to-y 1350 slides.pdf slide
```

`pdftoppm` מגיע עם `poppler` (`brew install poppler`). בדרך הזו אין בדיקת גופנים, אז פתח את ה-PDF ובדוק בעיניים לפני הייצוא. אל תשתמש ב-`--screenshot` של Chrome: בבדיקה שלנו הוא חתך את תחתית העמוד, ושם בדיוק נמצאים ההנדל והמספור.

**אם אין דרך לרנדר:** תן לו את קובץ ה-HTML ותגיד בשורה אחת מה חסר. הוא יכול לפתוח אותו בדפדפן ולבדוק, ולרנדר אחר כך. לא מגישים צילומי מסך של חלון דפדפן במקום קבצים.

## סדר העבודה

1. קרוסלה או רילס? תחליט ותגיד.
2. ציות לפני כתיבה (למעלה).
3. כתוב את הטקסט, שקופית אחרי שקופית, כרשימה ממוספרת שסולי סורק בעשר שניות.
4. שלושת השערים (אנושיות, זיהוי, ציות), על כל טקסט השקופיות בקובץ אחד, שורה לכל שקופית:

```bash
python3 humanize.py slides.txt -o slides.clean.txt --report
python3 detect.py slides.txt slides.clean.txt
python3 ethics.py slides.clean.txt --context carousel
```

את הדפוסים המסומנים כתוב מחדש ביד (הפירוט ב-`/ig-human`). כל FAIL מתוקן לפני שסולי רואה את הטקסט. כל REVIEW מוצג לו עם הקוד והסיבה. `ethics.py` תמיד אחרון, על הגרסה הסופית. אחרי הכלי, קרא את הטקסט מול `compliance.md` בעצמך.

5. **הכיתוב**, שבקרוסלה הוא תפקיד B ב-`/ig-caption`: יש לו עבודה אמיתית, כי השער כבר השתמש בשש המילים שלו. הכיתוב עובר שם את הבדיקות שלו (`ethics.py --context caption`).
6. הצג את הטקסט ואת הכיתוב, ואז את הקבלה. **חכה לאישור הטקסט.**
7. רק אחרי האישור, ורק כשאין יותר `{{...}}` או `[לבדיקה]`: בנה את ה-HTML ורנדר. אם סולי שינה טקסט, הרץ שוב את שלושת השערים על הטקסט המעודכן.
8. כלום לא עולה לאוויר. סולי מעלה בעצמו. על "כן" אחרי הרינדור, שורת ארכוב (C17): תאריך, ערוץ, סוג פריט ושורה ראשונה. תזכיר לו ש-C17 דורש לשמור גם את קבצי השקופיות עצמם, 3 שנים מהיום שהפוסט הפסיק להופיע. ב-Claude Code השורה נכתבת ל-`~/.claude/instagram/archive.md` (צור את התיקייה אם צריך). ב-claude.ai היא מוצגת כבלוק להעתקה, עם שורה שאומרת איפה לשמור.

```
הקרוסלה מוכנה לאישור
שקופיות:    {{n}}
שער:        {{n}} מילים
כיתוב:      תפקיד B, הוק בשורה 1, בקשה אחת, {{n}} האשטגים
פתוח:       {{n}} נקודות [לבדיקה] למלא לפני רינדור
ציות:       0 FAIL, {{n}} REVIEW ({{קודים}})

תאשר את הטקסט ואני בונה את הקבצים, או תגיד מה לשנות.
```
